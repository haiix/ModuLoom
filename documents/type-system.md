# 型システム設計

## 責務と保証範囲

ModuLoomのポート型は、配線候補、不正接続の防止、ノード入力直前の実行時検査、生成TypeScriptの
契約を担います。TypeScriptの完全な型検査器やJSON Schemaの代替ではありません。

- `number` は有限数、`array<T>` は全要素が `T`、`object` は `null` と配列以外の
  オブジェクト、`promise<T>` はthenable、`stream<T>` はAsyncIterableを検査します。
- カスタム型は配線時には型IDによるnominal型です。通常の入力検査はプレーンオブジェクトまで、
  フィールド構造はその型から生成されたValidateノードが再帰的に検査します。
- 型不一致の実行値は `INPUT_TYPE` として拒否します。値域、文字列形式、追加プロパティは型契約外です。

## TypeRefと保存表現

内部では型を `TypeRef { name, arguments }` へ正規化します。保存済みポートとカスタム型フィールドは
引き続き文字列なので、プロジェクト形式は `1.1.0` のままです。

```text
number
array<string>
promise<array<User>>
stream<number>
```

ジェネリック引数を持てるのは `array`、`promise`、`stream` で、引数はちょうど1個です。
大文字小文字の異なる組み込み名は正規化され、UIでは `Array<T>`、`Promise<T>`、`Stream<T>` と
表示します。旧ファイルの裸の `array`、`promise`、`stream` はそれぞれ `<any>` として評価しますが、
読み込み直後に保存文字列を書き換えないため、1.0.0/1.1.0ファイルを情報欠落なく扱えます。

## 接続互換性

| 出力                 | 入力                        | 判定                   |
| -------------------- | --------------------------- | ---------------------- |
| 同じ型引数を持つ同型 | 同型                        | 許可                   |
| `array<number>`      | `array<string>`             | 拒否                   |
| `array<T>`           | 旧 `array`（=`array<any>`） | 許可                   |
| 任意                 | `any`                       | 許可                   |
| `any`                | 任意                        | 許可し、入力時に再検査 |
| 任意                 | `unknown`                   | 許可                   |
| `unknown`            | `unknown` / `any`           | 許可                   |
| `unknown`            | それ以外                    | 拒否                   |
| 登録済みカスタム型   | `object`                    | 許可                   |
| `object`             | カスタム型                  | 拒否                   |

ジェネリック引数も同じ規則で再帰的に比較します。ノードライブラリの候補順位では、正規化後に
型引数まで一致する候補を、`any` によって互換になる候補より先に表示します。複合ノードの公開端子も
同じ型文字列を保持するため、グループ化・展開後にも要素型は失われません。

## カスタム型のネスト、循環、削除

フィールドには組み込み型、登録済みカスタム型、それらを包むコンテナ型を指定できます。
たとえば `array<Address>` や `promise<array<User>>` を利用できます。Validateは配列要素を再帰的に
検査し、生成コードにも同じ規則を埋め込みます。未知型と不正なジェネリックarityは保存操作または
プロジェクト読み込みで拒否します。

自己参照を含む直接・間接のカスタム型循環は拒否します。削除対象が別のカスタム型から、コンテナの
内側を含めて参照されている場合は削除を中止し、参照元を表示します。先に参照フィールドを変更または
削除してください。

## コード生成と移行方針

生成TypeScriptは `array<T>` を `Array<T>`、`promise<T>` を `Promise<T>`、`stream<T>` を
`AsyncIterable<T>`、`unknown` を `unknown` として出力します。カスタム型interfaceのフィールドと
パイプライン公開入力にも同じ変換を使うため、ランタイム契約と生成コードの型契約を一致させます。

保存形式のフィールド形状は変わらず、型文字列の文法だけを後方互換に拡張したため、新versionや
明示的な移行処理は不要です。将来、文字列から構造化JSONへ保存形式を変更する場合は、その時点で
versionを上げ、1.0.0/1.1.0からの明示的な変換を追加します。
