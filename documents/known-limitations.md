# 既知の制約と確認事項

この文書は、現行ソースコードから確認できた制約と、プロジェクト管理者へ確認したい事項をまとめたものです。

## 動作に影響する既知の問題

### 1. 2Dベクトル長プリセットの `math/sqrt` が未定義

`composite-vector-length` プリセットと、複合ノード画面から挿入できるベクトル長サンプルは `math/sqrt` を参照します。しかし `BUILTIN_NODES` に同じ `typeId` の定義がありません。

影響:

- 平方根ノードがキャンバスに描画されない
- 接続先ポート位置が見つからず、経路が完成しない
- 評価では未登録ノード定義として扱われる

対応案は `math/sqrt` ノードを追加し、TypeScript生成側にも実装を追加することです。

### 2. TypeScript生成とランタイムの差異

生成器のノードIDとランタイム定義に不一致があります。

- ランタイムは `logic/greater`、生成器は `logic/compare` を実装
- `logic/equal` の生成テンプレートがない
- `object/stringify` の生成テンプレートがない
- `math/sqrt`、`math/power`、`string/lowercase` など、片側にだけ記載されたIDがある
- 配列 Map／Filter の選択演算子や一部ノード状態が生成コードに反映されない
- ランタイムのゼロ除算はエラーだが、生成コードは0を返す
- 複合ノード専用の生成処理がなく、一般の既定処理に落ちる

生成された TypeScript は、そのまま本番利用せずレビューとテストが必要です。

### 3. 複合ノード展開時に外部接続が失われる

複合ノードを展開すると内部ノードと内部接続は復元されますが、複合ノードへ入る線と複合ノードから出る線は削除され、展開後の端子へつなぎ直されません。

### 4. プロジェクト読み込み検証が最小限

読み込み時に確認するのは、トップレベルがオブジェクトで `nodes` と `connections` が配列であることです。ノードID、ポートID、型、重複接続、循環、`customCode` の安全性は検証されません。

### 5. Stream のキャンセルは処理自体を停止しない

評価が無効になったとき、古い結果の画面反映は抑制しますが、タイマーや AsyncIterator を `AbortSignal` で中断しません。長時間または無限の外部ストリームへ拡張する場合は明示的な中断設計が必要です。

### 6. JSONから読み込んだ自作ノードは評価関数を失う

JavaScript 関数は JSON 化されないため、自作ノード定義の `evaluate` は保存ファイルに含まれません。`customCode` は保存されますが、現行の読み込み処理はそこから評価関数を復元しません。読み込んだ自作ノードを評価すると `def.evaluate is not a function` 相当のエラーになります。

自作ノードマネージャーで対象定義を編集し、保存し直すと関数は再作成されます。恒久対応には、読み込み時の式検証と評価関数再構築が必要です。

## 仕様上の制約

- ブラウザ更新時の自動復元はなく、JSON保存が必要
- 1つの入力ポートに接続できる線は1本
- カスタム型のフィールド型は組み込み型のみ
- カスタム型 Validate は必須フィールドの存在だけを確認し、値の型は確認しない
- 自作ノードは単一式で、式の値は先頭の出力ポートだけに設定
- 自作式は `new Function` で実行され、サンドボックス化されていない
- ストリーム収集は最大50件
- DAGステップ機能は実行順の表示であり、逐次実行デバッガーではない
- 保存JSONのバージョン移行機構がない

## 運用に関する不明点

- 対応ブラウザの正式なサポート範囲が未定義
- デプロイ先とリリース手順が未定義
- 貢献ルール、コードフォーマット、コミット規約が未定義

本番公開や外部コントリビューションを予定する場合は、これらの決定と文書化が必要です。
