# 利用ガイド

## 1. 画面構成

ModuLoom の画面は、上部ツールバー、中央キャンバス、ノードライブラリ、必要に応じて表示される DAG 実行デバッガーで構成されます。

上部ツールバーには、ノード追加、保存、読み込み、実行を常に表示します。画面幅が狭い場合はラベルを省いてアイコン表示になりますが、ボタンへフォーカスすると支援技術から操作名を確認できます。プリセット、カスタム型管理、複合ノード化、TypeScript 出力、DAG 実行デバッガー、型カラー凡例、全消去は「その他の操作」メニューにあります。メニューはキーボードの `Enter`／`Space` で開き、`Tab` で項目を移動し、`Enter` で選択、`Escape` で閉じられます。

リアクティブ評価の切り替え、即時実行、評価件数、ズーム、全体表示はキャンバス右下の操作パネルにあります。上部ツールバーとキャンバス操作パネルは 1280px、1024px、768px の各幅で折り返さず利用できます。

Undo／Redoボタンでは、ノード・接続・入力値・ラベルなどの編集を戻したり、やり直したりできます。ショートカットは `Ctrl+Z`／`Cmd+Z`、`Ctrl+Shift+Z`／`Cmd+Shift+Z`、または `Ctrl+Y` です。フォームへ入力中はブラウザ標準の文字編集を優先します。保存後に変更があるとツールバーへ「未保存」と表示され、未保存のままページを離れる場合はブラウザが警告します。パンとズームだけでは未保存になりません。

空白部分を右ドラッグすると矩形範囲のノードを選択できます。Shiftを押しながらノードをクリックするか矩形選択すると、現在の選択へ追加・解除できます。選択中のノードをドラッグすると全体が移動し、キャンバス左上の操作バーから複製、削除、左・右・上・下揃え、水平・垂直の等間隔配置を実行できます。複製では選択範囲内の接続だけが維持され、範囲外へ伸びる接続はコピーされません。`Ctrl+A`／`Cmd+A`ですべてのノードを選択でき、`Ctrl+C`／`Cmd+C`、`Ctrl+V`／`Cmd+V`、`Delete`／`Backspace` にも対応しています。キャンバスのパンは左ボタンのドラッグで行います。

### はじめてガイド

初回起動時は、画面左下のガイドが入力、処理、出力ノードの配置、ポート接続、評価結果の確認を順に案内します。グラフの状態に応じて次の手順へ自動で進み、完成時は最初の評価結果を表示します。ガイドはキャンバス全体を覆わないため、表示したまま編集できます。

「完成サンプルを見る」では、検証済みの四則演算パイプラインを直接読み込めます。ガイドをスキップまたは完了すると、その状態はブラウザ内に保持され、次回起動時は自動表示されません。「その他の操作」の「はじめてガイドを表示」からいつでも再表示できます。

## 2. 最初のグラフを作る

### ノードを配置する

1. 「ノードを追加」を押します。
2. カテゴリを開き、目的のノードを選びます。
3. ノードは現在表示中のキャンバス中央付近に追加されます。

ノード名はヘッダーのラベルをダブルクリックして変更できます。ヘッダーをドラッグするとノードを移動できます。

### ノードを接続する

1. 送信元ノード右側の出力ポートを押したままにします。
2. 送信先ノード左側の入力ポートまでドラッグします。
3. 型が互換で、循環を作らない場合に接続が作成されます。

1つの入力ポートに作成できる接続は1本です。接続済み入力へ新しい線をつなぐと、既存の接続が置き換わります。同じ出力は複数の入力へ分岐できます。

接続線をクリックすると中央に削除ボタンが表示されます。

### 接続できる型

次のいずれかを満たす場合に接続できます。

- 出力型と入力型が同じ
- どちらかが `any`
- カスタム型の出力を汎用 `object` 入力へ接続する

組み込み型は `number`、`string`、`boolean`、`array`、`object`、`promise`、`stream`、`any` です。ポート色は型を表し、ツールバーの「その他の操作」から型カラー凡例を確認できます。

## 3. キャンバス操作

- 空白部分を左ドラッグ: キャンバス移動
- 空白部分を右ドラッグ: 矩形範囲選択
- マウスホイール: カーソル位置を中心に拡大・縮小
- キャンバス右下の `−`／`+`: 縮小・拡大
- 倍率表示: 100% と初期位置へ戻す
- フィットボタン: 全ノードが見える倍率と位置へ調整
- ノードのゴミ箱: ノードと関連するすべての接続を削除
- 「その他の操作」の「キャンバスを全消去」: キャンバス全体を消去

倍率は 35%〜220% の範囲です。フォーム、セレクト、スクロール可能領域でのホイール操作はキャンバス拡大に使われません。

## 4. 評価とデバッグ

### リアクティブ評価

初期状態では「リアクティブ評価: ON」です。ノードの状態または接続が変わると、変更点とその下流ノードだけが再評価され、無関係な計算結果はキャッシュから再利用されます。位置、ラベル、ズーム、パンだけの変更では再計算されません。

OFF にすると自動評価を停止し、「実行」ボタンで手動評価できます。個々のノードにある再計算ボタンは、そのノードと下流だけを再評価します。

### DAG 実行デバッガー

「DAG実行デバッガー」を開いて「開始」を押すと、通常のリアクティブ評価とは別のデバッグセッションが先頭ノードの直前で停止します。「1ノード実行」は次の1件だけを評価し、「続行」は次の赤いブレークポイントまたは末尾まで評価します。ノードカードの丸印でブレークポイントを切り替えられます。

各ノードを選ぶと、解決済み入力、出力、実行時間、キャッシュ利用、前回評価との差分を確認できます。失敗したノードとその下流にはエラーの伝播経路が表示されます。PromiseやStreamの処理中は待機状態になり、「停止」で `AbortSignal` とStreamのキャンセルを通知します。「通常表示」でデバッグ用スナップショットを閉じても、通常のリアクティブ評価結果は維持されます。

### エラー表示

ノード評価中の例外は対象ノードに表示され、下流ノードには入力元エラーとして伝播します。UI は循環する接続の作成を拒否し、読み込みデータなどに循環が含まれる場合はグラフ全体をエラーにします。

## 5. プリセット

「その他の操作」のプリセット選択から完成済みグラフを読み込めます。選択すると現在のノードと接続は置き換わります。カスタム型と自作ノード定義はプリセット選択だけでは初期化されません。

利用できるプリセットは [ノードリファレンス](node-reference.md#プリセット) を参照してください。

## 6. カスタム型を作る

1. 「カスタム型定義」を開きます。
2. 型ID、表示名、色、説明を設定します。
3. 各フィールドの名前、組み込み型、必須指定、既定値を設定します。
4. 保存します。

型を保存すると、次の3種類のノードが自動生成されます。

- `Constructor`: フィールド入力から型付きオブジェクトを生成
- `Deconstruct`: 型付きオブジェクトをフィールドごとの出力へ分解
- `Validate`: 必須フィールドが `null`／`undefined` でないことを検証

初期状態では `User` と `Point2D` が登録されています。カスタム型のフィールド型は組み込み型に限られ、別のカスタム型をフィールド型として指定するUIはありません。

## 7. 自作ノードを作る

1. ノードライブラリの「自作ノード」を開きます。
2. 名前、説明、カテゴリを設定します。
3. 入力・出力ポートの名前、型、既定値を設定します。
4. `inputs` を引数として参照する単一の JavaScript 式を入力します。
5. テスト実行後、保存します。

例:

```js
inputs.a * inputs.b + 10;
```

保存された式の戻り値は、先頭の出力ポートへ格納されます。出力ポートを複数定義できるUIですが、現行実装では式の結果が設定されるのは先頭ポートだけです。

自作ノードの式はページ本体とは別の Web Worker で実行されるため、DOMやアプリ内部状態へ直接アクセスできません。実行は1秒で停止し、戻り値はJSONとしてシリアライズ可能かつ1MiB以下である必要があります。Promiseの戻り値にも対応します。

式では `inputs`、JavaScriptの式、標準の値操作、`Math`、`JSON`、`Promise`、Worker内タイマーを利用できます。DOM、通信、ブラウザストレージ、モジュール読込、Worker生成、動的コード生成、プロトタイプ操作は禁止され、対象ノードへエラーが表示されます。関数本体は JSON に保存されませんが、`customCode` から隔離評価関数を復元します。自作式を含むファイルの適用には読み込み画面で作成元を信頼するチェックが必要です。Worker境界は完全なセキュリティサンドボックスではないため、引き続き信頼できるファイルだけを適用してください。

## 8. 複合ノードと部分適用

複合ノードは、キャンバス上の処理経路を1つの再利用可能なノードへまとめます。

1. `グループ入力端子` を必要な引数の数だけ配置し、ポート名・型・テスト値を設定します。
2. 通常ノードを接続して処理を構成します。
3. 最終結果を `グループ出力端子` へ接続し、出力名・型を設定します。
4. 「複合ノード化」を開き、対象経路を確認します。
5. 名前と説明を設定し、元ノードを置換するか選びます。

対象範囲は、キャンバス上のすべてのグループ出力端子から上流へ逆向きに探索して決まります。通常の入力ノードやフォーム値を持つノードは固定値としてサブグラフ内に閉じ込められ、複合ノードの外部引数にはなりません。これが部分適用です。

複合ノードの展開ボタンで内部サブグラフに戻せます。複合ノードへ入る線は対応するグループ入力端子へ、出る線はグループ出力端子から再接続されるため、展開前後でデータフローが維持されます。保存データが壊れているなど対応端子を特定できない場合は、変更を適用する前に復元できない接続が表示されます。

## 9. 保存と読み込み

「保存」または `Ctrl+S`／`Cmd+S` で `moduloom-graph-YYYY-MM-DD.json` をダウンロードします。次の内容が保存されます。

- ノードと接続
- カスタム型
- 自作ノードと複合ノードの定義
- ズームとパン位置

「読み込み」または `Ctrl+O`／`Cmd+O` で JSON を選択します。ドラッグ＆ドロップにも対応しています。読み込みを確定すると現在のキャンバス、カスタム型、自作定義、表示位置が置き換わります。

ブラウザの Local Storage への自動保存はありません。必要な作業は明示的に JSON 保存してください。

## 10. TypeScript コード出力

「TSコード出力」はグラフを `evaluatePipeline` 関数へ変換します。画面からコピーするか、`pipeline-YYYY-MM-DD.ts` として保存できます。カスタム型がある場合は TypeScript の `interface` も生成されます。

組み込みノード、Promise／Stream、複合ノードはランタイムと同じ計算規則で生成されます。複合ノードは内部グラフへ展開されます。未対応の拡張ノード、循環、不正な複合境界がある場合は、暗黙の値へ置き換えず生成エラーを表示します。生成コードをアプリケーションへ組み込む前には、通常のコードと同様にレビューとテストを行ってください。詳細は [既知の制約](known-limitations.md) を参照してください。
